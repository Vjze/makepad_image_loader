# 2026-11-05

## 修复 makepad 版 `cargo run` 启动失败（HAL refused to open a session）
- 根因：makepad 新版（git 8049ae2，HAL 架构）在 Linux 上要求把进程主线程交给 HAL：先 `expect_main_loop()` 再 `run_main_loop()`，app 跑在独立线程。旧写法 `src/main.rs: fn main(){ img_loader::app::app_main() }` 直接调用 `app_main!` 宏生成在 lib 模块里的 `app_main()`，绕过了宏生成的真入口（它调用 `run_app()`），于是 `hal_open` 时 Linux 后端 `Shared::announced == false` → 报 "Linux windows require expect_main_loop/run_main_loop" + "the HAL refused to open a session"。
- 修复：`src/main.rs` 改为 `makepad_widgets::run_app(img_loader::app::app_main)`（等价于宏生成的 main）。另一种方案是装 cargo-makepad 用 `cargo makepad run`（由宿主进程托管），本机未安装。
- 顺带修复 `src/widgets/image_card.rs:66` 的 DSL 报错 `type mismatch for property border_radius: expected f32, got object`：`Image` 的 draw_bg（DrawImage）已有 f32 `border_radius`，`uniform(8.0)` 是声明对象；改成 `border_radius: 8.0`。
- 验证：`cargo build -p img_loader` 通过；`cargo run -p img_loader` 不再报 HAL 错误，`MAKEPAD_HAL_LOG=1` 下可见 Wayland 后端连接、shell startup 成功。剩余非致命日志：无硬件 Vulkan（ZINK 初始化失败，自动回退 GLES）、atspi EXTERNAL 认证被拒。

## 修复 Linux「标题栏下又多一行」（双标题栏）
- 原因：Wayland 默认向 KDE 请求服务端装饰（makepad HAL `wayland.rs` 里 `--wayland-decoration`/`MAKEPAD_WAYLAND_DECORATION` 默认 `server`），系统画一条标题栏；而 `Window` 在 Linux 下因 `caption_bar` 内含 `left_controls/filetree_btn`（`caption_contains_app_content == true`）又画一条自带 min/max/close 的 caption_bar，于是两行。Windows 无系统标题栏，所以按钮看起来就在标题栏上。
- 修复：`src/main.rs` 里 Linux 且用户未显式指定时设 `MAKEPAD_WAYLAND_DECORATION=client`（CSD），尊重 `MAKEPAD_WAYLAND_DECORATION=server` / `--wayland-decoration=server` 覆盖。验证 HAL 日志 `client_decorations=true`（KDE acknowledged）。
- 相关 API：`cx.set_linux_custom_window_chrome(true)` 只对 X11 隐藏 WM 装饰；Wayland 必须靠上面的装饰开关。

## 已知非致命日志噪音
- `[hal-gamepad] open /dev/input/eventN: Permission denied`：HAL 每秒扫描 /dev/input 探测手柄，用户不在 input 组或沙箱限制；makepad 无条件 `game_out(ENABLE)`，app 层无开关。桌面机可 `usermod -aG input` 或 udev 规则；否则过滤 stderr。
- `[atspi] No such property "ScreenReaderEnabled"`：makepad a11y 桥查 `org.a11y.Status`，KDE 未暴露该属性；`[atspi] notification channel full` 是事件通道溢出提示。均非致命，makepad 无 env 开关。
- `[hal] no hardware Vulkan ... rendering with GLES`、`[atspi] EXTERNAL authentication refused`：环境回退/认证警告，非致命。
